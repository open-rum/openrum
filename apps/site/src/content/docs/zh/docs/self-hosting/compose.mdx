这条路径用 Docker Compose 启动 Console、API、Ingest、Consumer、Worker、PostgreSQL、ClickHouse、Kafka 和 Redis。不在宿主机运行开发进程，也能体验完整产品。

<Aside type="caution" title="仅用于评估，不用于生产">
  当前 Compose 文件会生成演示数据，使用示例凭据与
  `APP_ENV=development`，并在宿主机开放依赖端口。它没有单机备份、HTTPS
  或故障切换方案。不要将其暴露在公网，也不要接入真实用户数据。生产环境请选择[推荐的 Kubernetes /
  Helm 路径](/zh/docs/getting-started/production-deployment/)，或独立的[单机 Docker 部署](/zh/docs/self-hosting/docker-production/)。
</Aside>

<Steps>

1. ## 准备 Docker

   安装带 Compose v2 的 Docker Engine 或 Docker Desktop。启动 Docker 后检查：

   ```sh
   docker info
   docker compose version
   ```

   请至少为本地 Docker 环境分配 8 GB 内存，并为镜像和数据库卷留出磁盘空间。默认占用宿主机端口 `4173`、`8081`、`5433`、`8123`、`9000`、`9092` 和 `6379`，启动前确认没有冲突。

   **完成标志：** 两条命令均成功，Compose 显示 v2 版本。

1. ## 获取源码与本地配置

   如果已经有仓库，请进入仓库根目录；否则执行：

   ```sh
   git clone https://github.com/openrum/openrum.git
   cd openrum
   ```

   如果 `deploy/compose/.env` 尚不存在，复制示例文件：

   ```sh
   cp deploy/compose/.env.example deploy/compose/.env
   ```

   已有 `.env` 时不要覆盖。它被 Git 忽略，包含仅供本地使用的示例密码；需要修改宿主机端口时也在这里调整。不要提交真实凭据。

   **完成标志：** 当前位于仓库根目录，且 `deploy/compose/.env` 已存在。

1. ## 启动服务

   ```sh
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml up -d --build
   ```

   首次运行会下载镜像、构建 OpenRUM、执行数据库迁移并生成演示项目。等待服务进入健康状态：

   ```sh
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml ps
   ```

   **完成标志：** `web`、`api`、`ingest`、`consumer`、`worker` 及四个数据服务健康。一次性的 `migrate`、`kafka-init` 和 `demo-seed` 任务显示 `Exited (0)` 属于正常情况。

1. ## 打开 Console 并验证

   ```sh
   curl --fail http://127.0.0.1:4173/health/ready
   ```

   打开 `http://127.0.0.1:4173`，用[快速开始](/zh/docs/getting-started/quickstart/)中的本地演示账号登录。请保持使用 `127.0.0.1`；换成 `localhost` 可能触发同源校验失败。

   **完成标志：** 健康检查有响应，Console 能进入演示项目。想核对真实可查询的数据，请继续阅读[确定性的演示数据](/zh/docs/getting-started/demo-data/)。

1. ## 查看或停止服务

   用 `ps` 或日志查看状态。停止容器但保留数据时使用 `down`：

   ```sh
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml logs --tail=100 api ingest consumer worker web
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml down
   ```

   重新启动时再执行第 3 步。`down` 会保留具名卷；**除非明确要删除本地数据库和演示数据，否则不要添加 `-v` 或 `--volumes`。** 启动或登录失败时阅读[故障排查](/zh/docs/self-hosting/troubleshooting/)。

</Steps>

对象存储可选：没有 Bucket 时核心监控仍能运行；Source Map Artifact 和映射后的源码定位需要配置[对象存储](/zh/docs/self-hosting/object-storage/)。
