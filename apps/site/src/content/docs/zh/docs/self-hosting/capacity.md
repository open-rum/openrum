---
title: 容量规划
description: 根据实测流量估算依赖与服务容量，而不是按演示数据推断。
appliesTo: Alpha
---

Compose 演示数据只用于产品体验，不能用于生产容量估算。规划应从实测 PV、自定义事件、
错误率、API 请求量和保留期开始。

## 需要收集的输入

- 峰值 EPS 与每日事件量
- 会话时长与每会话事件数
- 错误和 API 请求采样率
- 原始数据与聚合数据保留天数
- Source Map Artifact 大小与上传频率

先用采样率折算预期流量。项目速率限制按 Ingest 请求而不是事件计数；应使用实测的
每请求平均事件数换算峰值，并保留运维余量。公式和失败语义见[速率限制](/zh/docs/product/rate-limits/)。

## 依赖压力

结合[架构](/zh/docs/self-hosting/architecture/)阅读。Kafka 的保留余量决定依赖故障时还能
安全接收多久，因此优先估算。

| 依赖       | 重点指标                                 |
| ---------- | ---------------------------------------- |
| Kafka      | Produce 确认 P99、Consumer Lag、保留余量 |
| ClickHouse | 插入成功率、查询延迟、磁盘增长           |
| PostgreSQL | 连接数、控制面写延迟                     |
| Redis      | 内存与驱逐行为                           |
| 对象存储   | Artifact 大小、上传失败                  |
