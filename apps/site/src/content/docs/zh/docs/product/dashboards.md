每个项目都会先打开内置的默认仪表盘。所有人看到的默认仪表盘都一样，任何人都不能修改它。每位成员还可以为同一个项目保存多个命名的个人仪表盘，例如「流量」「API 健康」「发布观察」。修改你的仪表盘不会影响任何其他人。

## 默认仪表盘

默认仪表盘由 OpenRUM 定义，始终排在仪表盘列表的最前面。它从上到下依次是：

- **核心指标：** 会话数、PV、UV、错误率、API 失败率，以及 LCP、INP、CLS 的 P75，每项都带相比上一周期的变化。
- **趋势：** 会话数与上一周期对比、PV 与 UV、各设备 PV、API 请求结果、错误数与 LCP。
- **优先关注：** Top 页面、浏览器与国家分布、各版本错误、各国概况表、Top 问题与慢 API。

默认仪表盘把每种模块都至少用了一次，也可以借它了解仪表盘能画哪些图。

默认仪表盘可以像其他仪表盘一样编辑。保存时，OpenRUM 会用你的修改创建一个名为「我的仪表盘」的个人仪表盘并打开它。默认仪表盘保持原样，对你和其他人都不变。

## 个人仪表盘

点击页面顶部的仪表盘名称，即可在默认仪表盘与你自己的仪表盘之间切换，也可以新建、重命名、调整顺序或删除当前仪表盘。

- 新仪表盘可以从空白、默认布局、模板（电商经营概览、流量与会话、性能、API 健康、错误分析、业务指标）开始，也可以复制当前仪表盘。电商经营概览展示收入、订单数、客单价和购买漏斗，需要上报 `view_item`、`add_to_cart`、`begin_checkout` 和 `purchase` 自定义事件，并在 `purchase` 里用名为 `amount` 的数值记录订单金额。
- 每个仪表盘有自己的草稿并独立保存。若它已在其他设备上被修改，保存会被拒绝而不是覆盖对方；重新加载后再编辑即可。
- 普通的仪表盘地址会打开你在这台设备上最近使用的仪表盘。每个仪表盘都有自己的地址，链接会保留当前的时间与环境。
- 每人每个项目最多 20 个个人仪表盘，每个最多 24 个模块。默认仪表盘不计入这个上限。

## 模块

| 模块     | 展示内容                                                                 |
| -------- | ------------------------------------------------------------------------ |
| 指标卡   | 所选时间范围的一个数值，以及相比上一周期的变化                           |
| 时间趋势 | 一个或多个指标随时间的变化，可选面积、折线或柱状，并可叠加上一周期虚线   |
| 堆叠趋势 | 整体的各个组成部分随时间的变化：几个互不重叠的指标，或一个指标按维度拆分 |
| 维度分布 | 一个指标按维度展示为排行条、表格或圆环                                   |
| 排行表   | 一个指标按分组排行，每行带变化与迷你趋势                                 |
| 指标表   | 多个指标按分组并排，可按任意一列排序                                     |

模块库按数据领域组织：流量与会话、性能、API、错误、业务指标、用户行为。供你自己搭建的空白模块在「自定义」里。把鼠标移到页面顶部的齿轮上，即可编辑仪表盘或添加模块。

模块跟随页面的时间范围与环境。模块也可以带自己的筛选，例如版本、路由、国家/地区、浏览器、设备、事件类型或事件名称，具体取决于指标。

## 指标目录

模块从 OpenRUM 定义的指标目录中选择指标，而不是编写查询。每个指标都读取已有的聚合数据，所以仪表盘始终很快，也由目录决定哪些组合是有意义的。

| 分组       | 指标                                                                             |
| ---------- | -------------------------------------------------------------------------------- |
| 流量与会话 | PV、用户数、会话数、错误数、API 请求数、错误率、API 失败率                       |
| Web Vitals | LCP、INP、CLS 的 P75                                                             |
| API        | 请求数、失败数、4xx/5xx/网络错误及其占比、延迟 P50/P75/P95                       |
| 错误       | 错误事件数、受影响用户与会话、活跃 Issue、新增 Issue                             |
| 业务指标   | 自定义事件某个数值的总和、按采样率还原的总和、平均值、最小值、最大值、P50 与 P90 |
| 用户行为   | 页面浏览、路由导航、点击与自定义事件的事件次数、触发用户数与触发会话数           |

## 在一张图上对比多个事件

想看支付流程，可以添加一个时间趋势，选择「事件次数」，按「事件名称」拆分，再选择要对比的事件，例如 `checkout_started`、`payment_succeeded` 和 `payment_failed`。每个事件是同一坐标轴上的一条线，按你选择的顺序排列，最多 9 条。

- 不选择事件时，图表展示次数最多的事件。可以按事件类型筛选，避免页面浏览和点击挤占位置。
- 某个时间桶里没有发生的事件会留空，而不是画成 0。
- 事件次数可以堆叠，因为每个事件只计一次。触发用户数和会话数不能堆叠：同一个人可能触发其中好几个事件。
- 成功加失败不一定等于发起的次数，因为有人会中途放弃，所以通常用折线更诚实。

## 保证数字可信的规则

- **一张图一个单位。** 画在一起的指标单位相同；按采样率还原的数量不能与未还原的数量共用坐标轴。
- **只有整体的组成部分才能堆叠。** 堆叠图需要能相加的指标，例如三种 API 请求结果占比，它们的分母相同。错误率、分位数和去重用户不能按分组相加，因此没有「其他」分组，不计算占比，也不能画成圆环。
- **4xx 不算失败。** API 失败指网络层失败和 5xx 响应。请求结果构成图把 4xx 单独展示为占全部请求的比例。
- **新增 Issue** 指在时间范围内首次出现、或沉寂 30 天后复发的 Issue。「有史以来第一次」无法在有界查询中回答，而且本身也受聚合数据保留期限制。
- **错误指标按 5 分钟或更粗的粒度绘制**，因为它们就是这样存储的。
- **仪表盘上的 Web Vitals 只有 P75。** 其他分位数以及 FCP、TTFB 在性能页查看。
- **业务指标需要填写数值名称**，例如 `amount`，可以按国家/地区、设备、浏览器、来源或自定义事件属性拆分，但不能同时按国家或浏览器筛选。
- **用户行为指标一次只按一个维度拆分。** 事件名称、国家/地区、设备、浏览器、来源或自定义事件属性都可以拆分图表，但按国家拆分的图表不能再按浏览器筛选。

所有图表遵循共享的约 30 个时间桶的点数预算。没有数据的时间桶留空，不画成 0。

## 模块报错时

查询扫描量过大的模块会提示查询超出预算。缩短时间范围，或增加环境、版本、路由筛选即可，其他模块不受影响。
