This path runs the Console, API, Ingest, Consumer, Worker, PostgreSQL, ClickHouse, Kafka and Redis in Docker Compose. It is the fastest way to try the full product without running development processes on your host.

<Aside type="caution" title="For evaluation, not production">
  This Compose file runs Demo seeding, uses example credentials and `APP_ENV=development`, and
  publishes dependency ports on the host. It has no single-host backup, HTTPS or
  failover setup. Do not expose it to the internet or send real user data to it. For production,
  choose the [recommended Kubernetes / Helm path](/docs/self-hosting/kubernetes/) or the separate
  [single-host Docker deployment](/docs/self-hosting/docker-production/).
</Aside>

<Steps>

1. ## Prepare Docker

   Install Docker Engine or Docker Desktop with Compose v2. Start Docker, then check:

   ```sh
   docker info
   docker compose version
   ```

   Allocate at least 8 GB of memory to the local Docker environment and leave room on disk for images and database volumes. The default host ports are `4173`, `8081`, `5433`, `8123`, `9000`, `9092`, and `6379`; check that they are free.

   **Success:** Both commands complete and Compose reports a v2 version.

1. ## Get the source and local configuration

   If you already have the repository, enter its root directory. Otherwise:

   ```sh
   git clone https://github.com/openrum/openrum.git
   cd openrum
   ```

   If `deploy/compose/.env` does not already exist, make a local copy of the example:

   ```sh
   cp deploy/compose/.env.example deploy/compose/.env
   ```

   Keep an existing `.env` rather than overwriting it. This file is ignored by Git and contains local-only example passwords. Change host ports there if needed; do not commit real credentials.

   **Success:** You are in the repository root and `deploy/compose/.env` exists.

1. ## Start the stack

   ```sh
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml up -d --build
   ```

   The first run downloads images, builds OpenRUM, applies database migrations and seeds a Demo Project. Wait for the services to become healthy:

   ```sh
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml ps
   ```

   **Success:** `web`, `api`, `ingest`, `consumer`, `worker` and the four data services are healthy. The one-time `migrate`, `kafka-init` and `demo-seed` jobs may show `Exited (0)`; that is expected.

1. ## Open the Console and verify

   ```sh
   curl --fail http://127.0.0.1:4173/health/ready
   ```

   Open `http://127.0.0.1:4173` and sign in with the local Demo account in [Quickstart](/docs/getting-started/quickstart/). Keep the same `127.0.0.1` origin; switching to `localhost` can fail same-origin checks.

   **Success:** The health endpoint responds and the Console opens the Demo Project. To check actual observations, follow [Deterministic Demo data](/docs/getting-started/demo-data/).

1. ## Stop or inspect the stack

   To inspect a service, use `ps` or logs. To stop without deleting data, use `down`:

   ```sh
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml logs --tail=100 api ingest consumer worker web
   docker compose --env-file deploy/compose/.env \
     -f deploy/compose/docker-compose.yml down
   ```

   Run the command in step 3 to start it again. Named volumes remain after `down`. **Do not add `-v` or `--volumes` unless you intend to delete the local databases and Demo data.** For startup or login failures, see [Troubleshooting](/docs/self-hosting/troubleshooting/).

</Steps>

Object storage is optional. Core monitoring works without a Bucket; Source Map Artifacts and mapped frames require an [object-storage provider](/docs/self-hosting/object-storage/).
