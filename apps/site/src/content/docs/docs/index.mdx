OpenRUM is an open-source, self-hosted frontend monitoring platform built for high throughput and reliable production operation. Deploy an Instance and add the Browser SDK to monitor errors, performance, API requests, logs, and user behavior from a single Console.

## What it covers

| Capability               | What you get                                                                                                      | Read                                                 |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| Errors and investigation | JavaScript errors grouped into Issues, Source Map stack restoration, and the Session timeline around each error.  | [Investigate an issue](/docs/product/investigation/) |
| Performance and APIs     | Core Web Vitals, route performance, and request latency and failures.                                             | [Performance](/docs/product/performance/)            |
| Behavior analytics       | Page Views, visitors, Custom Events, funnels, paths, and retention.                                               | [Behavior analytics](/docs/product/analytics/)       |
| Logs                     | Structured browser logs searchable by severity, user, and Session.                                                | [Logs](/docs/product/logs/)                          |
| Dashboards and alerts    | Project dashboards and metric alerts delivered to Feishu/Lark or a Webhook.                                       | [Alerts](/docs/product/alerts/)                      |
| Privacy by default       | No raw input values, headers, or bodies in automatic capture; headers and bodies only for APIs a project opts in. | [Privacy](/docs/self-hosting/security/privacy/)      |

## What runs

An Instance runs five application services: the Console web server, API, Ingest, Consumer, and Worker. They use four required dependencies: PostgreSQL for accounts, projects, and settings; ClickHouse for events and analytical queries; Kafka as the ingestion buffer; and Redis for caching and rate limits. Object storage is optional and only needed for Source Map uploads. See [Architecture](/docs/self-hosting/architecture/) for how events flow through them.
