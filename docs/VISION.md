## Founder

- **Name:** lijie
- **Expertise:** 程序员，擅长前端开发，熟悉大型 Web/H5 项目的工程与质量问题
- **Background:** 公司项目日均 PV 达千万级，长期需要同时理解真实用户行为和定位前端错误。希望打造一套开源、自部署、体验优秀的产品，把 Google Analytics 式行为分析与 Sentry 式错误诊断融合在一个连贯工作流中，并用真实高流量项目验证产品。

## Purpose

- **Who you help:** 希望自主掌握数据，并在一个产品里同时完成用户行为分析与前端错误诊断的 Web 产品团队
- **Problem you solve:** 行为分析和错误监控通常分散在不同工具中，指标、用户、会话、版本与错误上下文无法自然贯通；现有开源自部署方案又常把部署能力放在体验之前，难以成为团队每天愿意使用的产品。
- **Desired transformation:** 团队从“在分析平台发现现象、再去监控平台拼接线索”，转变为“在同一体验中理解用户做了什么、哪里流失、发生了什么错误以及如何修复”。
- **Why you:** 创始人擅长前端开发，理解 SDK 接入、用户体验和前端诊断的真实细节，同时拥有千万级日 PV 的验证环境，能够把产品体验与工程可靠性一起打磨。

## Product

- **Name:** OpenRUM
- **One-liner:** 开源自部署的 Web 用户行为分析与错误监控平台。
- **How it works:** 团队创建项目并接入轻量 JavaScript SDK；几分钟内即可看到 PV、UV、访问趋势、自定义事件、用户与会话分群以及错误影响。用户能从国家、设备、浏览器、来源或自定义属性等维度理解行为，再沿同一用户、会话、页面和版本上下文下钻到错误、Source Map 源码与关联请求。
- **Key capabilities:**
  - 轻量前端 SDK、自动页面/会话采集、自定义事件与属性、身份和隐私控制
  - PV/UV、事件趋势、国家/设备/浏览器等分群，以及漏斗、路径和留存分析
  - 错误采集与稳定聚合、Source Map 解析、面包屑、会话上下文和版本关联
  - 行为指标与错误之间的统一下钻和可分享调查视图
  - 自部署所需的权限、告警、性能/API 辅助诊断、用量可见性和 Kubernetes 运维能力
- **Platform:** web
- **Market differentiation:** 以开源、自部署和高完成度体验为基础，把 Google Analytics 式的行为洞察与 Sentry 式的错误诊断连接在同一数据模型和调查路径中；用户不必在“好用的闭源 SaaS”和“可控但难用的自建工具”之间二选一。
- **Magic moment:** SDK 接入几分钟后，用户看到真实访问与关键行为，发现某一浏览器或国家的转化异常，并能直接下钻到受影响会话及对应错误的源码位置。

## Audience

- **Primary user:** 负责 Web 产品体验和线上质量的前端负责人或产品工程师，希望既看懂用户行为，也能快速定位造成体验或转化异常的前端错误。
- **Secondary users:**
  - 需要漏斗、路径、渠道和用户分群的产品经理与数据分析人员
  - 使用事件详情、Source Map 和行为上下文排查问题的业务前端开发者
  - 负责自部署、数据治理、权限和升级的前端基础设施或平台工程师
- **Current alternatives:** Google Analytics 或同类分析产品加 Sentry 的组合，以及 PostHog、Matomo、GlitchTip、日志平台和自建报表等单点或组合方案。
- **Frustrations:** 行为平台能说明“发生了什么”却很难解释前端为何失败，错误平台能定位异常却缺少完整产品行为视角；跨工具的用户、会话、事件和版本口径不一致，自部署产品的界面与接入体验又往往不够成熟。

## Business

- **Revenue model:** free
- **90-day goal:** 发布可自部署的开源 MVP，完整打通 JavaScript SDK、PV/UV、自定义事件、基础分群/漏斗、错误聚合、Source Map 与行为上下文；接入真实项目验证日常分析和错误诊断两条核心路径。
- **6-month vision:** 形成可持续使用的 Google Analytics + Sentry 开源替代方向，补齐路径/留存、Session Replay、告警和版本回归；获得第一批外部生产用户、真实案例和社区贡献者。
- **Constraints:** 以前端擅长的创始人为主、兼职或小团队推进，需要补齐 Go、ClickHouse、Kafka 和 Kubernetes 有状态服务运维能力；必须控制分析查询自由度和事件基数，在千万级 PV 下守住 SDK 开销、隐私、查询体验与运维可靠性。
- **Go-to-market:** 以 GitHub 开源和自部署文档为入口，用高完成度 Demo、行为分析与错误联动案例、真实规模基准和前端社区内容吸引试用；公司项目作为生产验证场，而不是产品只服务于内部替换。

## Brand Voice

- **Personality:** 开放、务实、透明、克制；像一个值得信任的工程伙伴，不制造焦虑，也不隐藏成本与数据处理方式。
- **Tone of voice:** 简洁、友好、以事实和下一步行动为中心。成功示例：“SDK 已收到第一批事件，质量总览将在一分钟内更新。”错误示例：“Source Map 未匹配到当前版本，请检查 release 名称和上传路径。”告警示例：“结算页错误率在 10 分钟内升至 3.2%，主要影响 Chrome 128；查看新增问题。”

## Tech Stack

- **App type:** web
- **Frontend:** React + TypeScript + Vite — 贴合创始人的前端优势，适合构建高交互监控控制台；配合 TanStack Router、Query、Table，ECharts、Tailwind CSS 与 shadcn/ui
- **Backend:** Go — 适合实现高吞吐接入网关、消费处理和查询 API，运行开销可控，便于在 Kubernetes 中水平扩展
- **Database:** ClickHouse + PostgreSQL — ClickHouse 存储和分析高基数、追加型监控事件，PostgreSQL 管理用户、组织、项目、权限、告警规则和配置等事务数据；Kafka 负责削峰与解耦，Redis 用于限流、缓存和短期去重，阿里云 OSS 保存 Source Map、Session Replay、附件和冷数据
- **Auth:** 内置账号 + 可选 OIDC — MVP 提供开箱即用的管理员初始化和本地账号，密码采用 Argon2id、会话使用安全 Cookie；通过统一认证接口为后续 Keycloak、Authentik 或企业身份系统预留 OIDC 扩展
- **Payments:** None — 前期完全免费、开源和自部署，不设计付费功能
- **Analytics:** OpenRUM 独立自监控项目 + Prometheus — 通过 dogfooding 验证产品分析能力，并用独立的基础设施指标监控接入、消费、查询和存储链路，避免单一监控闭环失效
- **Email:** 通用 SMTP + Webhook — 保持自部署和供应商中立，支持邮件及通用 Webhook 告警，后续可扩展飞书、钉钉、企业微信和 Alertmanager 通知器
- **Error tracking:** OpenRUM 独立自监控项目 — 平台前后端错误进入隔离项目，并配合 Kubernetes 日志和 Prometheus 健康指标保留故障时的旁路诊断能力
