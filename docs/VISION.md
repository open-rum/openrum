## Founder

- **Name:** lijie
- **Expertise:** 程序员，擅长前端开发，熟悉大型 Web/H5 项目的工程与质量问题
- **Background:** 公司项目日均 PV 达千万级，目前使用阿里云 ARMS，但实际体验复杂且成本高。希望自研一套参考 Sentry、但覆盖范围不止错误追踪的前端监控平台，并先在公司真实流量中验证。

## Purpose

- **Who you help:** 负责多个高流量 Web/H5 项目、同时承受质量与成本压力的前端负责人和前端基础设施工程师
- **Problem you solve:** 现有前端监控平台在大流量下成本快速增长，迫使团队降低采样率、缩短数据保留时间或牺牲监控覆盖面；错误、性能、请求和用户行为数据又彼此割裂，定位问题效率低。
- **Desired transformation:** 团队从“监控成本不可控、数据分散、问题难复现”，转变为“以可预测成本完整掌握前端质量，并能沿统一上下文快速完成发现、定位与验证”。
- **Why you:** 创始人既有较强的前端工程经验，也正在千万级日 PV 的真实业务中承受 ARMS 的体验和成本问题，能够从 SDK 接入、前端诊断到生产规模验证完整地定义并打磨产品。

## Product

- **Name:** OpenRUM
- **One-liner:** 统一采集和分析前端错误、性能、请求与用户行为。
- **How it works:** 团队创建项目并接入轻量 JavaScript SDK；几分钟内即可在质量总览看到真实 PV、UV、错误率、Web Vitals 和慢 API。用户可以从异常指标下钻到聚合问题、具体事件、Source Map 还原后的堆栈、请求与行为时间线，并通过筛选、告警和版本对比推动问题闭环。
- **Key capabilities:**
  - 前端 SDK、框架适配器与自定义事件上报，支持采样、批处理、压缩和隐私控制
  - 错误采集与聚合、Source Map 解析、上下文时间线和版本关联
  - Web Vitals、页面性能、资源性能与 API 请求监控
  - PV/UV、用户行为分析与 Session Replay
  - 多维查询、告警、用量统计和成本治理
- **Platform:** web
- **Market differentiation:** 面向高流量前端场景，以开源自部署、数据自主和透明可控的采样与存储策略显著降低监控成本；同时用统一事件上下文贯通错误、性能、请求和用户行为，而不是把它们拆成互不关联的工具。
- **Magic moment:** SDK 接入后无需复杂配置，用户在几分钟内看到项目的真实 PV、错误率、Web Vitals 和慢 API，并能立即下钻到一个可定位的问题实例。

## Audience

- **Primary user:** 负责多个千万级流量 Web/H5 项目的前端负责人，需要控制监控成本、掌握整体质量，并推动开发团队快速定位和修复线上问题。
- **Secondary users:**
  - 负责 SDK、监控基础设施和接入规范的前端基础设施工程师
  - 使用事件详情、Source Map 和行为上下文排查问题的业务前端开发者
  - 关注版本质量、回归风险和稳定性指标的测试、质量与技术管理人员
- **Current alternatives:** 当前主要使用阿里云 ARMS，也会参考 Sentry 的错误追踪体验；其他数据通常散落在埋点分析、日志、APM 和自建报表中。
- **Frustrations:** ARMS 在高流量场景收费昂贵、使用体验不佳且信息层级复杂；不同工具之间上下文割裂，采样和保留策略不透明，定位一次问题常需跨多个系统拼接线索。

## Business

- **Revenue model:** free
- **90-day goal:** 完成可运行的 MVP，包含 JavaScript SDK、PV/UV、错误监控、Source Map、API 与性能监控、自定义上报及 Kubernetes 部署；接入公司真实项目，在千万级日 PV 流量下稳定运行并开始替代部分 ARMS 能力。
- **6-month vision:** 在公司核心项目形成稳定的内部替代方案，将监控综合成本降低至少 50%；补齐用户行为、Session Replay、告警和版本回归分析，并沉淀可公开的架构、性能与成本案例，为开源社区增长奠定基础。
- **Constraints:** 以前端擅长的创始人为主、兼职或小团队推进，需要补齐 Go、ClickHouse、Kafka 和 Kubernetes 有状态服务运维能力；必须严格控制 MVP 范围，并在千万级 PV 下关注 SDK 开销、数据量、查询性能和基础设施成本。
- **Go-to-market:** 先通过公司内部真实流量完成生产验证和 ARMS 替代，形成可信的成本与性能案例；随后通过 GitHub 开源、技术文章、架构复盘和前端社区传播吸引中大型研发团队试用和贡献。

## Brand Voice

- **Personality:** 开放、务实、透明、克制；像一个值得信任的工程伙伴，不制造焦虑，也不隐藏成本与数据处理方式。
- **Tone of voice:** 简洁、友好、以事实和下一步行动为中心。成功示例：“SDK 已收到第一批事件，质量总览将在一分钟内更新。”错误示例：“Source Map 未匹配到当前版本，请检查 release 名称和上传路径。”告警示例：“结算页错误率在 10 分钟内升至 3.2%，主要影响 Chrome 128；查看新增问题。”

## Tech Stack

- **App type:** web
- **Frontend:** React + TypeScript + Vite — 贴合创始人的前端优势，适合构建高交互监控控制台；配合 TanStack Router、Query、Table，ECharts、Tailwind CSS 与 shadcn/ui
- **Backend:** Go — 适合实现高吞吐接入网关、消费处理和查询 API，运行开销可控，便于在 Kubernetes 中水平扩展
- **Database:** ClickHouse + PostgreSQL — ClickHouse 存储和分析高基数、追加型监控事件，PostgreSQL 管理用户、组织、项目、权限、告警规则和配置等事务数据；Kafka 负责削峰与解耦，Redis 用于限流、缓存和短期去重，阿里云 OSS 保存 Source Map、Session Replay、附件和冷数据
- **Auth:** 内置账号 + 可选 OIDC — MVP 提供开箱即用的管理员初始化和本地账号，密码采用 Argon2id、会话使用安全 Cookie；通过统一认证接口为后续 Keycloak、Authentik 或企业身份系统预留 OIDC 扩展
- **Payments:** None — 前期完全免费、开源和自部署，不设计付费功能
- **Analytics:** OpenRUM 独立自监控项目 + Prometheus — 通过 dogfooding 验证产品分析能力，并用独立的基础设施指标监控接入、消费、查询和存储链路，避免单一监控闭环失效
- **Email:** 通用 SMTP + Webhook — 保持自部署和供应商中立，支持邮件及通用 Webhook 告警，后续可扩展飞书、钉钉、企业微信和 Alertmanager 通知器
- **Error tracking:** OpenRUM 独立自监控项目 — 平台前后端错误进入隔离项目，并配合 Kubernetes 日志和 Prometheus 健康指标保留故障时的旁路诊断能力
