## Build Philosophy

1. **Each phase ships something usable.** 每个阶段结束都可启动、演示和验证，不把集成风险堆到最后。
2. **Infrastructure before features.** 先建立协议、迁移、测试和本地依赖，后续功能沿稳定边界扩展。
3. **Magic moment first.** Phase 4 结束前必须实现“五分钟接入、60 秒可见、下钻到源码线索”。
4. **Test as you go.** 每个任务都包含验证；SDK、协议、指纹和查询必须有固定 fixtures。
5. **Progressive enhancement.** 先做固定调查路径和有界查询，再增加高级分析。
6. **Review before proceeding.** 每阶段独立分支/PR，使用 CodeRabbit 或同类 review agent，修完问题再合并。
7. **Behavior and errors share one product model.** 每引入一种分析或诊断能力，都必须保留 user/session/page/release 上下文与双向下钻。
8. **Privacy by default.** query、body、Cookie 和敏感 Header 默认不进入系统；任何放宽都必须显式设计和测试。

4. Keep one task to roughly one focused 15–45 minute coding session; split a task before coding if it cannot fit.
5. At phase end, run the full phase verification, update status/current phase, create the documented branch and open a PR.
6. Let CodeRabbit or another independent reviewer inspect the PR; address findings on the same branch and merge only when clean.

### Phase Review Workflow

Branch: `phase-{N}/{phase-slug}`
PR title: `Phase {N}: {Phase Title}`

PR body must contain the phase goal, task range/count, manual verification steps and reference sections used. If GitHub/PR review is unavailable, record an equivalent review in docs/reviews/phase-N.md; understand that skipping independent review increases security and regression risk.

### Session Tips

- Do not skip tasks; ordering resolves dependencies.
- Do not invent visual tokens. If docs/design.md is missing when styling begins, run the Design System skill first.
- Preserve user changes and inspect the current workspace before editing.
- Never mark a task complete before its Verify condition passes.
- After each phase, run the app and exercise its demoable outcome manually.
- Update the header to `Status: X/106` and set Current Phase to the first phase with unchecked tasks.
